# 代码规范

本文件约束 `instaace-fusion` 仓库内所有语言（Python / Kotlin / QML）的代码。
提交前请对照本文件的检查清单自检。

---

## 一、注释

### 默认不写注释

代码应当自解释。命名清晰、结构扁平的代码不需要注释复述它做了什么。

### 允许的注释只有五类

| 类型 | 例子 |
|---|---|
| 解释「为什么」而非「是什么」 | `# MediaCodec 的 i-frame-interval 只接受整数秒，因此拿不到 16 帧密集关键帧` |
| 记录非显而易见的约束与坑 | `# 文件名必须 ASCII：中文经 AAPT 打包后变成乱码，assets.open 会失败` |
| 公共 API 文档注释 | Python docstring、Kotlin KDoc |
| 复杂算法思路 | 索引 protobuf 的就地替换策略、moov 骨架重建顺序 |
| 危险操作警告 | `# 这里会改写相机卡索引，调用前必须已确认卡结构` |

### 禁止的注释

- **分节横幅**：`# ---- 版本 ----`、`/* ---- 存储卡 ---- */`、`// ---------- 原语`
  （Qt 样式表字符串里的 `/* ---- xxx ---- */` 属于 CSS 内容，不受此限）
- **教程语气**：`# 这里我们先把文件读进来`
- **免责式说明**：`注意：这里可能需要调整`
- **示例代码残留在注释里**
- **空的 TODO**：`# TODO` 后面必须写清具体要做什么
- **emoji**：`★`、`✓`、`⚠` 等一律不用（界面文案除外）
- **中英混排且无必要**

### 密度

每个文件注释行数不超过总行数的 10%。
超了说明代码本身需要重构，而不是删注释。

### 函数文档注释

Python 的公共函数与 Kotlin 的公开 API 必须有文档注释，且按第四节的
边界政策四段式书写。私有小函数不必逐个写。

## 二、边界政策（每个非平凡函数必须交代四件事）

### 1. 前置条件（Preconditions）

调用方必须满足什么才允许调用：

- 参数类型、范围、非空
- 依赖的外部状态（文件存在、目录可写、权限已授予、ffmpeg 可用）
- 时序要求（必须先初始化、不能并发调用）

### 2. 后置条件（Postconditions）

函数正常返回时保证什么：

- 返回值含义与取值范围
- 产生了哪些副作用（写了哪些文件、改了哪些状态）
- 资源是否已释放

### 3. 不变量（Invariants）

执行期间必须始终成立的条件：

- 哪些字段不被修改
- 锁的持有范围
- 线程/进程生命周期

### 4. 失败方式（Failure modes）

按类型列出，不允许只写「可能抛异常」：

| 分类 | 处理要求 |
|---|---|
| 用户错误 | 抛 `ValidationError` / 返回明确错误信息，提示用户怎么改 |
| 系统错误（可重试） | 标注 `retryable=True`，说明重试条件 |
| 系统错误（不可重试） | 直接失败，不重试，保留完整上下文 |
| 用户取消 | 抛 `CanceledError`，与失败区分开 |

### 输入的校验

- 空值、null、类型、范围、长度、格式**全部显式校验**
- 校验在**服务端 / 核心层**做，不依赖前端隐藏按钮
- 不使用 `any` / `Any`；公共接口给出明确的类型定义

### 错误处理

- **禁止吞异常**：`except Exception: pass` 只允许出现在进程/线程/句柄清理路径
- **禁止空 catch**
- 捕获后必须做三件事之一：记录日志、转换类型重抛、降级并告知用户
- 失败路径必须有测试用例覆盖

### 资源生命周期

- 定时器、监听器、连接、文件句柄：写明何时创建、何时释放
- 协程作用域必须在组件销毁时取消（Compose 用 `DisposableEffect`）
- 子进程必须在 `finally` 中 kill + wait
- 临时文件必须在成功与失败两条路径上都清理

### 并发假设

- 写明是否线程安全、是否幂等
- 跨线程写 UI 状态必须切主线程（Compose 的 `mutableStateOf` 只能在主线程写）
- 并行任务失败时，说明是中止整批还是仅当前任务回退

### 数据量

- 明确单次处理的条数上限
- 大文件/大列表必须有分页、背压或流式处理
- 缓存必须有失效策略，不能一次失败就永久禁用

## 三、回退与降级

自动降级必须满足三条：

1. **降级前记录原因**：日志里写清「哪个能力失败、失败信息、降级到哪条路径」
2. **降级不得静默**：用户能感知最终使用了哪条路径
3. **降级失败要还原成真实错误**：不能因为降级尝试过就把错误吞成成功或取消

硬解 → 软解这类回退，必须：

- 清理失败产生的半成品文件
- 标记该能力本次不可用，避免同批任务反复踩坑
- 回退成功时不得把整批任务标记为失败
- 用户主动取消必须优先于回退（取消不触发回退）

## 四、自我审查清单（提交前逐条勾）

- [ ] 全部文件语法检查通过（`py_compile` / Kotlin 编译零 `e:`）

- [ ] 线程/协程边界正确，UI 状态只在主线程写
- [ ] 资源在成功与失败两条路径都释放
- [ ] 边界值（空列表、单元素、超大值、负数）行为正确

- [ ] 没有分节横幅
- [ ] 没有教程语气、免责说明、空 TODO、emoji
- [ ] 注释密度不超过 10%
- [ ] 公共 API 都有文档注释

### 内容

- [ ] 没有真实设备序列号、本机绝对路径、密钥、口令
- [ ] 版本号在 `core.py` / `insta_core.py` / `build.gradle.kts` / 界面文案四处一致

## 六、这个实现不负责什么

明确列出边界之外的事，避免被误认为承诺：

- **不保证相机兼容性**：产物结构按真机原片复刻，但未在多机型验证
- **不校验源视频内容合法性**：用户需自行确保有权导入
- **不备份相机卡**：导入会改写索引，备份是用户责任
- **不做云端处理**：全部本地完成，不承担数据同步
- **不保证跨版本配置兼容**：协议或索引格式变更时会要求重新同意/重新扫描
