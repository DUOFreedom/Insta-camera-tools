技术原理

相机判断「这是不是我自己录的」，靠的不是文件名，而是三重校验。这一页把三层拆开讲，并说明两个机型的参数为什么不同。

第一层

编码结构

主视频与 LRV 代理文件的编码参数要求
文件 编码 参数
VID_*.mp4 HEVC / hvc1 1920×1080，30fps，-g 16，-bf 0
LRV_*.lrv H.264 / avc1 1280×720，-g 16，-bf 0

hvc1 与 hev1 不同：hvc1 把参数集放在 hvcC box 里，hev1 内联在码流中。相机只认前者。

-bf 0 关掉 B 帧是硬性要求。相机解码器按「无 B 帧、关键帧固定间隔」设计，带 B 帧的文件能写进去但播放会花屏或卡死。

第二层

inst box

这是影石的私有 box，装在 MP4 的 moov 里，存着缩略图、创建时间、机型标识等元数据。没有它，相机把文件当外部拷入的普通视频，不进相册。

位置
MP4 的 moov box 内
内容
缩略图、创建时间、机型标识等元数据
模板要求
inst 的结构在不同机型、不同固件间有差异，不能凭空构造——必须用同一台相机、同一版本固件录出的真实原片当模板，把它的 inst 整体移植过来，再改写里面的时间戳和缩略图。
trak 要求
模板片应包含 3 条 trak（视频、音频、tmcd 时间码）。缺 tmcd 轨会导致部分固件版本不识别。

缩略图（896×512 NV12）必须在 rebuild_media 之前写入 inst，顺序错了文件能识别但播放黑屏。

第三层

索引登记

相机开机时扫描 DCIM 目录，但相册显示的是索引文件里的内容。两个文件都必须改：DCIM\fileinfo_list.list（文件列表）与 DCIM\.editinfo_list.list（编辑信息，隐藏文件）。索引是 protobuf 格式。

索引关键字段与易错点
字段 含义 易错点
f7 创建时间 必须 14 位 YYYYMMDDHHMMSS，不带序号；写成 9 位会「能列出但打不开」
f9 inst box 在文件中的字节偏移 不是文件大小，不是 inst 的长度
meta 与文件内 inst 的 meta 逐字节一致 有任何字节不同都可能被判为非法

.editinfo_list.list 带隐藏与只读属性，必须用 r+b 原地改写；用 wb 会 PermissionError，用「先删再建」会丢文件属性导致相机不认。

机型差异：关键帧间隔不是常数

Ace Pro 2 的原片里，主视频与代理文件的关键帧间隔都是 16；GO Ultra 的主视频是 120、代理是 10。这个值不是猜的，是从原片 stss（sync sample）表里实际数出来的帧间隔，再按它写进新的码流。

代理文件的编码器也不同：Ace Pro 2 用 H.264（avc1），GO Ultra 用 HEVC（hvc1）。 如果按 Ace Pro 2 的假设把 avc1 写死，GO Ultra 上生成的文件在相机相册里根本不会出现 —— 而文件本身能正常播放、电脑上的播放器也打得开，所以这个错误在电脑上完全没有症状。

同理，inst box 里记录的 GOP 必须写真实值。只改编码参数、不改元数据里的字段，相机读到的仍是「帧间隔对不上」。

为什么模板必须同机型、同固件

inst box 是一段相机私有的二进制元数据：机型、固件版本、录制参数、缩略图、时间码都在里面。程序的做法是拿一段同机型原片的 inst box 当骨架，替换掉与文件相关的字段（时长、帧数、偏移、缩略图），再整段写进新文件。

骨架不符机型时，字段布局可能一致但取值语义不同（GOP、代理轨的 handler、音轨数），相机校验失败后按外来文件处理： 不进相册、不给封面、不参与回放。这类失败不在导入时报错，只在相机上表现为「什么都没有」。

缩略图也有位置要求：896×512 的 NV12 数据必须在重建 moov 之前写进去，重建之后再补会让文件偏移全部错位。
