InstaAceImporter · v1.0.0

把普通视频变成影石 Ace Pro 2 的「原生」素材

转码成相机原生结构（VID + LRV）、移植 inst box、登记相机索引。插回相机，相册里能识别、能播放、封面正确。

Ace Pro 2 只认自己录出来的文件

把手机或相机拍的视频拷进卡里，相册里要么看不见，要么能列出来但点了打不开，要么没有封面。

相册里看不见

缺少相机私有的 inst box，文件被当成外部拷入的普通视频，不进相册。

能列出来但点了打不开

编码结构不合规：不是 hvc1、带 B 帧、关键帧间隔错位。相机解码器按「无 B 帧、关键帧固定间隔」设计，不是 hvc1 就不认。

没有封面

缩略图没有写进 inst box，或者写入顺序不对——文件能识别，但播放黑屏。

影石相机工具解决的就是这件事：把任意普通视频重新封装成相机认可的结构，写进相机索引，插回相机后就和原生录制的素材表现一致。

它做三件事，缺一不可

三步是一条链，任何一步缺失都会在相机里露出破绽。

1

转码

做什么
视频流转成 HEVC hvc1 1080p、关掉 B 帧、关键帧间隔对齐；同时生成 H.264 的 .lrv 代理文件。
不做会怎样
相机拒绝播放。
2

移植

做什么
把相机私有 inst box 从模板片移植进新文件，写入缩略图与元数据。
不做会怎样
相机视为外来文件，不显示。
3

登记

做什么
在 fileinfo_list.list 与 .editinfo_list.list 中写入条目。
不做会怎样
相册里不出现。

功能

桌面端 PyQt5 应用。从批量排队到断点续跑，处理的都是「一次几百个文件」这种真实场景。

导入与转码

  • 开工前体检

    开跑前 1 秒内检查 ffmpeg、源文件、输出目录、剩余空间、卡是否可写、模板片是否存在，有问题当场拦下。

  • 随时取消

    转码中途点取消，ffmpeg 进程干净退出，不留孤儿进程。

  • 断点续跑

    中断后重新打开，会问「只跑未完成的 N 条」还是「全部重跑」。

  • 同名封面

    a.mp4 旁边有 a.jpg / a.png 就自动用它当封面。

  • 批量排队

    一次拖几百个文件进来也没问题。

运行体验

  • 三阶段进度

    转码 / 移植 / 登记分开显示，不糊成一条进度条。

  • 防休眠

    处理长片时系统不会中途睡过去。

  • 硬件加速

    自动探测并优先使用 QSV / NVENC / AMF，不可用时回落到软件编码。

  • 离线回归

    31 项测试，不需要真机也能跑。

  • 运行日志

    写入 %LOCALAPPDATA%\InstaAceImporter\，出问题可回溯。

两个文件都要：只放 ffmpeg.exe 不够，程序需要用 ffprobe.exe 读取源文件信息。

快速开始

四步，不需要命令行。

  1. 1

    把相机卡插到电脑，或者先指定一个输出文件夹。

  2. 2

    拖入要导入的视频（支持多选、也支持直接拖整个文件夹）。

  3. 3

    点「开始」，等进度条走完。

  4. 4

    把卡插回相机，打开相册。

首次使用建议先拿一个短视频试一遍，确认相册里能看到、能播放、封面正常，再批量处理。

常见问题

七条，覆盖绝大多数「导进去了但相机不认」的情况。

点开始没反应，或者报错找不到 ffmpeg

把 ffmpeg.exe 和 ffprobe.exe 放进 exe 同目录的 bin\ 文件夹，或者装进系统 PATH。

注意两个文件都要，只放 ffmpeg.exe 不够——程序需要用 ffprobe.exe 读取源文件信息。

视频导进去了，但相机相册里看不到

按顺序检查三件事：

  1. 编码结构是否达标——主视频必须是 HEVC hvc1、1080p、无 B 帧、关键帧间隔 16
  2. inst box 是否移植成功——用卡内真机原片当模板，模板片不能是别的机型录的
  3. 索引是否登记——见下方「技术原理」

三者任一缺失都会导致相册里没有这个文件。

相册里能看到条目，但点了打不开

通常是索引字段写错，最常见两种：

  • f7 时间戳不是 14 位纯数字 YYYYMMDDHHMMSS（写成 9 位带序号就会这样）
  • f9 偏移不是 inst box 在文件内的真实字节偏移（写成了文件大小也会这样）
相册里出现了 0KB 打不开的条目

索引里多登记了 .lrv 文件。规则是只登记主视频，不登记 LRV。

重新导入时程序会覆盖修正，不需要手动删。

超过 4GB 的长视频会失败吗

不会。重封装对 32 位 size 与 64 位 largesize box 头、以及 stco / co64 两种分块偏移表都做了完整支持。

Windows 提示「未知发布者」或杀毒软件报毒

PyInstaller 打包的未签名程序会触发 SmartScreen，这是预期行为。点「更多信息 → 仍要运行」即可。

杀软误报通常是启发式规则对 PyInstaller 启动器敏感，加白名单即可，不需要关闭实时防护。

能导入到相机的哪个位置？会不会覆盖原有素材

写入 DCIM 目录，文件名按相机规则生成（VID_YYYYMMDD_HHMMSS_000.mp4），文件名冲突时自动递增序号。

不会覆盖已有素材。索引写入前会重读现有内容，只追加/替换自己的条目。

技术原理

相机判断「这是不是我自己录的」，靠的不是文件名，而是三重校验。

第一层

编码结构

主视频与 LRV 代理文件的编码参数要求
文件 编码 参数
VID_*.mp4 HEVC / hvc1 1920×1080，30fps，-g 16，-bf 0
LRV_*.lrv H.264 / avc1 1280×720，-g 16，-bf 0

hvc1 与 hev1 不同：hvc1 把参数集放在 hvcC box 里，hev1 内联在码流中。相机只认前者。

-bf 0 关掉 B 帧是硬性要求。相机解码器按「无 B 帧、关键帧固定间隔」设计，带 B 帧的文件能写进去但播放会花屏或卡死。

第二层

inst box

这是影石的私有 box，装在 MP4 的 moov 里，存着缩略图、创建时间、机型标识等元数据。没有它，相机把文件当外部拷入的普通视频，不进相册。

位置
MP4 的 moov box 内
内容
缩略图、创建时间、机型标识等元数据
模板要求
inst 的结构在不同机型、不同固件间有差异，不能凭空构造——必须用同一台相机、同一版本固件录出的真实原片当模板，把它的 inst 整体移植过来，再改写里面的时间戳和缩略图。
trak 要求
模板片应包含 3 条 trak（视频、音频、tmcd 时间码）。缺 tmcd 轨会导致部分固件版本不识别。

缩略图（896×512 NV12）必须在 rebuild_media 之前写入 inst，顺序错了文件能识别但播放黑屏。

第三层

索引登记

相机开机时扫描 DCIM 目录，但相册显示的是索引文件里的内容。两个文件都必须改：DCIM\fileinfo_list.list（文件列表）与 DCIM\.editinfo_list.list（编辑信息，隐藏文件）。索引是 protobuf 格式。

索引关键字段与易错点
字段 含义 易错点
f7 创建时间 必须 14 位 YYYYMMDDHHMMSS，不带序号；写成 9 位会「能列出但打不开」
f9 inst box 在文件中的字节偏移 不是文件大小，不是 inst 的长度
meta 与文件内 inst 的 meta 逐字节一致 有任何字节不同都可能被判为非法

.editinfo_list.list 带隐藏与只读属性，必须用 r+b 原地改写；用 wb 会 PermissionError，用「先删再建」会丢文件属性导致相机不认。
